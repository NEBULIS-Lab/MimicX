# Video to Policy

Run commands from the repository root unless a subshell changes directory.
Complete [dependency setup](../dependencies/README.md) first. All GPU operations
below require an allocated GPU in your execution environment.

## Paths

```bash
export MIMICX_ROOT="$PWD"
export MIMICX_BACKEND="$PWD/third_party/unitree_rl_mjlab"
export PYTHONPATH="$MIMICX_ROOT:$MIMICX_BACKEND:$MIMICX_BACKEND/src:${PYTHONPATH:-}"
export WANDB_MODE=offline
export MUJOCO_GL=egl
```

Place an authorized single-person video at `data/input/skill.mp4`. Provide the
GVHMR environment's Python and your separately licensed body models below.

## Reconstruct and Retarget

```bash
python scripts/reconstruct_video.py \
  --video data/input/skill.mp4 --output data/reconstruction \
  --python third_party/GVHMR/.venv/bin/python --verbose
```

Add `--static-camera` only for a stationary source camera. GVHMR stores its
`hmr4d_results.pt` under the video-specific output directory; inspect that
output, then provide its actual path:

```bash
python scripts/retarget_gvhmr_to_gmr.py \
  --input data/reconstruction/skill/hmr4d_results.pt \
  --output data/motions/skill.pkl --robot unitree_g1 \
  --body-models /path/to/licensed/body_models --fps 30
python scripts/convert_gmr_to_mjlab_csv.py \
  --input data/motions/skill.pkl --output data/motions/skill.csv --print-summary
```

Use the GMR/retargeting environment for the retarget command and switch back
to the tracking environment for conversion to the simulator reference:

```bash
(
  cd "$MIMICX_BACKEND"
  python scripts/csv_to_npz.py --robot g1 \
    --input-file "$MIMICX_ROOT/data/motions/skill.csv" \
    --output-name skill --input-fps 30 --output-fps 50 --device cuda:0
)
```

Output: `third_party/unitree_rl_mjlab/src/assets/motions/g1/skill.npz`.
The converter computes body pose and velocity fields using the robot model.
Reference-only visualization is a kinematic inspection, not a trained rollout.
Check joint count, duration, root motion and contacts before training. The G1
29-DoF tracking policies and 23-DoF policies are not interchangeable.

## Train a Warmstart

```bash
export MOTION_FILE="$MIMICX_BACKEND/src/assets/motions/g1/skill.npz"
(
  cd "$MIMICX_BACKEND"
  python scripts/train.py Unitree-G1-Tracking-MimicX-Curriculum \
    --motion-file "$MOTION_FILE" \
    --env.scene.num-envs 1024 \
    --agent.seed 101 --agent.run-name skill_warmstart \
    --agent.max-iterations 1000 --agent.save-interval 50
)
```

This is an example budget, not a guarantee of task completion. Warmstarts are
task-specific. Checkpoints are saved under
`$MIMICX_BACKEND/logs/rsl_rl/g1_tracking/<timestamp>_skill_warmstart/`.
Keep the entire run directory, including configuration dumps and normalizers.

## AutoRefine

Set `CHECKPOINT` to an actual saved model and `HORIZON` to the full evaluation
budget in 50 Hz steps. Freeze the same evaluation budget across methods.

```bash
export CHECKPOINT="$MIMICX_BACKEND/logs/rsl_rl/g1_tracking/<run>/model_999.pt"
export HORIZON=800
python scripts/create_loop_manifest.py \
  --task-id skill --motion-file "$MOTION_FILE" \
  --checkpoint "$CHECKPOINT" --horizon "$HORIZON" \
  --seed 101 --train-iterations 250 --max-iterations 1 \
  --devices 0 --output runs/skill/loop.yaml
python scripts/autorefine/run_closed_loop.py \
  --manifest runs/skill/loop.yaml --run-dir runs/skill/refinement --mode prepare
python scripts/autorefine/run_closed_loop.py \
  --manifest runs/skill/loop.yaml --run-dir runs/skill/refinement --mode execute
```

`prepare` records commands without executing them. `execute` runs incumbent
verification, failure mining, three bounded candidates, continuation and
repeated candidate verification. Re-run the same command to resume after an
interruption. Use a new run directory for changed inputs or budgets.

`state.json` records the selected checkpoint; `loop_summary.json` records the
stop reason. Each iteration preserves its failure report, proposal JSON,
training/evaluation logs and `selection.json`. Protection of the current policy
is a completed gate decision, not a missing result. Training reward alone
does not decide acceptance.

The default manifest uses three verification seeds and a 20% relative
worst-body guard. For more refinement rounds increase `--max-iterations` when
creating a new manifest. Multi-device IDs are local visible indices; one
candidate training job uses one device and same-device jobs are serialized.

## Controlled Comparisons

`scripts/autorefine/launch_paper_matrix.py` expands task, method and seed
manifests and provides resumable individual jobs. Run `--help` for its
`--prepare`/`--run-job` interfaces. A runnable example is generated by
`scripts/create_comparison.py` from an existing loop manifest:

```bash
python scripts/create_comparison.py --loop-manifest runs/skill/loop.yaml \
  --failure-window 200 280 --priority-bodies right_wrist_yaw_link \
  --output-dir runs/skill/comparison-config
python scripts/autorefine/launch_paper_matrix.py --prepare \
  --matrix runs/skill/comparison-config/matrix.yaml \
  --run-dir runs/skill/comparison --gpus 0
```

Inspect the generated job ledger before running its queue inside your compute
allocation. The Python runtime must contain the tracking dependencies for
checkpoint-dimension inspection. Reports are produced with
`scripts/autorefine/summarize_paper_matrix.py`.

The static comparison's failure window and priority bodies must come from
your task diagnosis; the values above only demonstrate the interface. Default
comparison references are identical across methods. A separately prepared
reference can be supplied explicitly to the comparison generator.
